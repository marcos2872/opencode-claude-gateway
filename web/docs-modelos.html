Modelos e resolução

Você escolhe o modelo no cliente via /model, alimentado por GET /v1/models. O POST /v1/messages aceita três formas e resolve nesta ordem.

Ordem de resolução

  1. alias do gateway — claude-opencode-go-glm-5-3-flash;
  2. ref direta provider/model — opencode-go/glm-5.3-flash;
  3. id simples — glm-5.3-flash.

Sufixos: [1m] / [200k] são removidos antes de resolver (o Claude Code os anexa a ids desconhecidos) e #variant seleciona uma variante — ver Variantes.

Id ambíguo

Um id simples presente em mais de um provider ordena por nome qualificado e usa o primeiro, registrando o WARN ambiguous model id, using first; prefer an alias or provider/model com a lista de candidatos. Não é erro, mas é uma escolha que você não fez: prefira alias ou ref.

Exemplo real: claude-sonnet-5 existe em github-copilot/ e opencode/ — o Copilot ganha por ordem alfabética. Ver Aliases para fixar o destino.

Sem model na request

O gateway usa o default_model do config; sem ele, o primeiro alias em ordem alfabética. Só isso — o gateway nunca traduz um modelo em outro: o gateway_model no log é sempre o id que o cliente pediu.

config.toml 
default_model = "claude-opencode-go-deepseek-v4-1-flash"

Free-tier

Modelos opencode/* dão 403 fora do OpenCode e ficam ocultos do /v1/models a menos que include_free_tier = true. Atenção: a ocultação afeta o picker, não a resolução por id simples — um id que só existe no free-tier ainda pode ser escolhido por uma chamada que você não fez.

Pacotes e protocolo

O protocolo de saída vem do pacote do provider no catálogo: Anthropic faz passthrough para {baseURL}/messages; OpenAI-compatible vai para /chat/completions; linhas Go GPT/Grok/Muse vão para /responses. Providers que falam o protocolo nativo do Google não têm tradutor e são ocultados no boot, com WARN.
