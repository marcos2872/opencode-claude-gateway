Instalação

O ocg é um único binário. O que ele precisa de verdade é de um OpenCode v2 já autenticado — o gateway reaproveita esse login em vez de pedir credenciais de novo.

Pré-requisitos

  • OpenCode v2 instalado e logado (opencode auth login). É ele quem autentica no Console e fornece o catálogo de modelos.
  • curl e, opcionalmente, o gh CLI para baixar o binário.

Binário da release

shell 
# 1. URL do binário mais recente
$ URL=$(gh release view --repo marcos2872/opencode-claude-gateway --json assets \
      --jq '.assets[] | select(.name=="ocg-linux-x86_64") | .url')
# 2. baixe, torne executável e mova para o PATH
$ curl -L "$URL" -o /tmp/ocg
$ install -m 0755 /tmp/ocg ~/.local/bin/ocg
# 3. confira
$ ocg --version

Sem gh, copie o link direto da página da release no GitHub.

A partir do código

shell 
# no clone do repositório
$ cargo install --path .
# ou direto do git
$ cargo install --git https://github.com/marcos2872/opencode-claude-gateway

Primeiro run

O primeiro run cria ~/.config/opencode-claude-gateway/config.toml com todas as opções comentadas. Depois:

shell 
$ ocg --start
$ ocg --status
$ curl -s http://127.0.0.1:3737/health

A seguir, aponte seu cliente: Claude Code CLI ou Claude Desktop.

Migrando do frank-opencode

Troca limpa, sem fallback: pare o daemon antigo, mova o config e suba o novo.

shell 
$ frank-opencode --disable
$ mkdir -p ~/.config/opencode-claude-gateway
$ mv ~/.config/frank-opencode/config.toml ~/.config/opencode-claude-gateway/config.toml
$ ocg --start

FRANK_PORT/FRANK_CONFIG/FRANK_AUTH_TOKEN viraram OCG_*; o state mudou de ~/.local/share/frank-opencode/ para ~/.local/share/opencode-claude-gateway/.
