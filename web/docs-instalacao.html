01 · começando índice

Instalação

O ocg é um único binário. Instalar é baixar, rodar ocg install e abrir o Claude Code com ocg claude — sem editar a configuração global do Claude. O único pré-requisito real é um OpenCode v2 já autenticado: o gateway reaproveita esse login em vez de pedir credenciais de novo.

Antes de começar

  • OpenCode v2 instalado e logado (opencode auth login). É ele quem autentica no Console e fornece o catálogo de modelos.
  • Claude Code no PATH (claude --version) — o ocg claude e os plugins dependem dele.
  • curl para baixar o binário. O gh CLI é opcional (só facilita achar a URL da release).

Um comando, três resultados. ocg install cria o config.toml como cópia do config.example.toml, só trocando o auth_token por um gerado. Depois, ocg claude abre o CLI apontado para o gateway sem tocar em ~/.claude, e ocg --status mostra a saúde e o uso por modelo da semana.

1 · Baixar o binário

Escolha o seu sistema. A release oficial publica o binário Linux x86_64; nos outros sistemas, compile a partir do código (passo seguinte) — leva alguns minutos e não precisa de nada além do Rust.

shell · Linux x86_64 
# baixa o binário da última release e deixa executável
$ URL=$(gh release view --repo marcos2872/opencode-claude-gateway \
      --json assets --jq '.assets[] | select(.name=="ocg-linux-x86_64") | .url')
$ mkdir -p ~/.local/bin
$ curl -L "$URL" -o ~/.local/bin/ocg
$ chmod +x ~/.local/bin/ocg
$ ocg --version

Sem gh, copie o link direto de github.com/marcos2872/opencode-claude-gateway/releases. Garanta que ~/.local/bin está no PATH (a maioria das distros já inclui).

shell · macOS (Apple Silicon e Intel) 
# compila do código (precisa do Rust: rustup.rs)
$ cargo install --git https://github.com/marcos2872/opencode-claude-gateway
$ ocg --version

O cargo install coloca o binário em ~/.cargo/bin/ocg, que o rustup já deixa no PATH. Se preferir Homebrew, veja a nota abaixo.

PowerShell · Windows 
# compila do código (precisa do Rust: rustup.rs)
PS> cargo install --git https://github.com/marcos2872/opencode-claude-gateway
PS> ocg --version

No Windows o binário fica em %USERPROFILE%\.cargo\bin\ocg.exe. O ocg --enable (auto-start) usa systemd, então não vale no Windows — use ocg --start ou crie uma tarefa de inicialização. O restante (gateway, launcher, plugins) funciona igual.

2 · Ou compilar do código

Qualquer sistema, com Rust instalado:

shell 
$ git clone https://github.com/marcos2872/opencode-claude-gateway
$ cd opencode-claude-gateway
$ cargo install --path .

3 · ocg install: config pronto

  1. Gere a configuração

    Cria config.toml (permissão 0600) como cópia do config.example.toml, só com o auth_token substituído por um token gerado de 64 hex. Os aliases que o exemplo fixa vêm exatamente como estão lá.

    shell 
    $ ocg install
created /home/você/.config/opencode-claude-gateway/config.toml
  auth_token: 9f2c…  (copie se for configurar um cliente à mão)

  2. (Opcional) Instale os plugins

    --agent-usage (alias --agent-use) põe a cota do OpenCode Go na linha de status; --browser dá ao Claude Code as abas do Chrome. Eles vêm do marketplace do repositório e já recebem base_url e auth_token certos.

    shell 
    $ ocg install --agent-usage --browser   # --browser precisa de bun no PATH

  3. Suba o gateway

    O ocg install não sobe nada. Suba em background com --start — ou pule este passo, porque o ocg claude sobe sozinho se preciso.

    shell 
    $ ocg --start
$ ocg --status

  4. Abra o Claude Code

    ocg claude escreve um claude-settings.json só da sessão e roda claude --settings <arquivo>. Como --settings tem precedência sobre ~/.claude/settings.json, o gateway vale só nesta sessão e a sua configuração global continua intacta. Escolha o modelo no /model.

    shell 
    $ ocg claude                 # abre o CLI no gateway
$ ocg claude -- --resume    # argumentos depois de -- vão para o claude

Quer o gateway em toda sessão? Em vez do launcher, aponte o ~/.claude/settings.json uma única vez — é a alternativa explícita. Veja Claude Code CLI. O Claude Desktop usa o gateway inference.

Onde ficam os arquivos

O ocg segue as pastas padrão de cada sistema (XDG no Linux). Se quiser abrir o config e editar, é o primeiro caminho da tabela.

config
~/.config/opencode-claude-gateway/config.toml
estado
~/.local/share/opencode-claude-gateway/ (ocg.pid, ocg.port, ocg.pair, ocg.session, ocg.stats.json, ocg.log)
auto-start
~/.config/systemd/user/ocg.service
config
~/.config/opencode-claude-gateway/config.toml
estado
~/.local/share/opencode-claude-gateway/ (mesmos arquivos do Linux)
auto-start
sem systemd — use ocg --start ou um LaunchAgent
config
%APPDATA%\opencode-claude-gateway\config.toml
estado
%LOCALAPPDATA%\opencode-claude-gateway\ (pid, porta, par, sessão, stats, log)
auto-start
sem systemd — use ocg --start ou uma tarefa do Agendador

Para usar outro config sem sair do padrão: --config CAMINHO ou a variável OCG_CONFIG.

4 · Editando o config

Abra o config.toml num editor e reinicie o gateway (ocg --stop && ocg --start) — ele lê o arquivo no boot. As chaves mais usadas:

Chaves mais editadas do config.toml
chavepara quê
auth_tokenCredencial que o cliente envia. Já vem gerada; troque se quiser.
default_modelModelo quando a request omite model. Fixe um que você queira, não o primeiro alfabético.
[aliases."<id>"]Prende um id que o Claude pede (ex.: claude-sonnet-5) a um provider/model que você escolhe.
[tiers."<ref>"]Tier de família para o Desktop (haiku/sonnet/opus/fable/mythos).
[disabled]Esconde refs do /v1/models.

Referência completa: config.toml · aliases: Aliases · autenticação: Autenticação.

Migrando do frank-opencode

Troca limpa, sem fallback: pare o daemon antigo, mova o config e suba o novo.

shell 
$ frank-opencode --disable
$ mkdir -p ~/.config/opencode-claude-gateway
$ mv ~/.config/frank-opencode/config.toml ~/.config/opencode-claude-gateway/config.toml
$ ocg --start

FRANK_PORT/FRANK_CONFIG/FRANK_AUTH_TOKEN viraram OCG_*; o state mudou de ~/.local/share/frank-opencode/ para ~/.local/share/opencode-claude-gateway/.
