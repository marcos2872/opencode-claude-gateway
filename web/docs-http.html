Endpoints HTTP

Uma única borda de cliente, no dialeto da Anthropic. Tudo em 127.0.0.1; nada sai para a Anthropic.

Endpoints

token* = exige auth_token apenas quando ele está setado.

Endpoints servidos
endpointautho que faz
GET /healthabertook / degraded / starting, contagem de modelos, default_model efetivo e last_error do load no boot.
GET /v1/modelstoken*Aliases claude-<provider>-<model>, com [1m] quando a janela real ≥ 1M e context_window. Alimenta o /model.
POST /v1/messagestoken*Aceita alias, ref provider/model e id simples; sufixo #variant quando o catálogo declara variantes. Streaming via SSE.
POST /v1/messages/count_tokenstoken*Pacotes Anthropic: proxy para {baseURL}/messages/count_tokens com fallback local; demais pacotes: estimativa local por partes.
GET /usagetoken*Cota do OpenCode Go (janelas de 5h/semanal/mensal + créditos do console) que o mod agent-usage lê. Cache de 60s; sempre 200, com o erro numa linha.
GET /statustoken*Contadores de uso por modelo dos últimos 7 dias, em JSON — é o que o ocg --status lê quando o daemon está no ar.

/health

No boot o catálogo é tentado até 6 vezes com backoff (~2s → 16s) enquanto vier vazio — comum quando o serviço do OpenCode ainda está aquecendo. Esgotadas as tentativas com 0 modelos, last_error fica preenchido e o status vira degraded, em vez de parecer ok com catálogo vazio. Não há refresh automático depois do boot.

shell 
$ curl -s http://127.0.0.1:3737/health \
    | jq '{status, models, default_model, last_error}'

Formato de erro

Sempre no formato de erro da Anthropic, com tipos conhecidos (not_found_error, authentication_error, invalid_request_error, api_error):

resposta 
{
  "type": "error",
  "error": {
    "type": "not_found_error",
    "message": "unknown model 'foo' (see GET /v1/models)"
  }
}

Uma falha do upstream no meio do stream é um evento error que encerra o stream — nunca um message_stop falso. Durante o silêncio do upstream o gateway injeta event: ping para o watchdog não travar.

Cache de prefixo

Nos caminhos traduzidos (Chat/Responses) o contador de cache do upstream aparece como usage.cache_read_input_tokens na resposta do /v1/messages — só quando > 0, então um miss mantém o formato antigo. O passthrough Anthropic repassa o usage verbatim.
