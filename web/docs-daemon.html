Daemon e CLI

O gateway roda como daemon em background. Ciclo de vida e auto-start são separados de propósito: --start/--stop nunca tocam no auto-start, e --enable/--disable nunca iniciam nem param um gateway em execução. O --status também mostra o uso por modelo da semana.

Flags

Flags do CLI
flaggrupoo que faz
--start [--port N]daemonSobe o filho destacado com --serve, espera /health e imprime os export do Claude Code.
--stopdaemonSIGTERM (drena streams SSE) e limpa o estado.
--statusdaemonVersão, se está rodando, porta, uptime, auto-start e os modelos mais usados nos últimos 7 dias (ver abaixo).
install [--agent-usage] [--browser]onboardingCria o config (cópia do example + token gerado) e, opcionalmente, instala os plugins. Nunca toca em ~/.claude. Veja Instalação.
claude [-- args]launcherSobe o gateway se preciso e abre o Claude Code com um --settings só da sessão. Veja Claude Code CLI.
--enableauto-startInstala e habilita o systemd user service (~/.config/systemd/user/ocg.service, ExecStart=<bin> --serve). Não inicia agora.
--disableauto-startRemove o auto-start. Não para um gateway rodando.
--serveforegroundServidor em primeiro plano (dev e filho do daemon). Logs no terminal via RUST_LOG.
--refreshpréviaImprime o catálogo que o boot carregaria (N modelos + aliases) e sai.

ocg --status e o uso por modelo

Além da saúde do daemon, o status resume os modelos mais usados nos últimos 7 dias, por tokens (entrada + saída reportados pelo upstream), com a participação de cada um no total e a conversão do alias:

shell 
$ ocg --status
ocg 0.4.1 · running (pid 4821, port 3737, healthy) · up 3h12m
auto-start: enabled

Most used models · last 7 days · 4.20M tokens · 1.20M cached
  claude-sonnet-5 → opencode-go/deepseek-v4.1-flash          58.3%  2.45M  312 req
  claude-opus-5 → github-copilot/gpt-6-luna                  22.1%  930.0K  138 req
  claude-haiku-4-5 → opencode-go/muse-spark-1.3               9.3%  390.0K   77 req
  opencode-go/glm-5.3-flash (direct ref)                      7.9%  330.0K   37 req
  claude-opus-4-8#fast → github-copilot/gpt-6-luna            2.4%  100.0K   15 req
  total                                                      100.0%  4.20M  579 req
  • Grava só requisições bem-sucedidas (2xx), com o usage que o upstream reportou — inclusive no streaming. Upstream que não reporta usage conta 0 tokens; as requisições continuam contadas.
  • Com o daemon no ar, o status lê GET /status (memória, mais novo); parado, lê o ocg.stats.json já gravado.
  • Buckets por dia (UTC), podados além de 7 dias. Persistidos a cada minuto e no shutdown. OCG_STATS_FILE sobrepõe o caminho.

Arquivos

  • Config: ~/.config/opencode-claude-gateway/config.toml — ou --config / OCG_CONFIG.
  • Estado: ~/.local/share/opencode-claude-gateway/ com ocg.pid, ocg.port, ocg.session, ocg.pair, ocg.stats.json (uso por modelo) e ocg.log. Todos criados 0600.
  • Launcher: claude-settings.json no mesmo diretório de estado — gerado e reescrito por ocg claude.
  • Log: ocg.log, só-append. Acompanhe com tail -f; o arquivo cresce com o uso.
  • Auto-start: ~/.config/systemd/user/ocg.service.

Debug por request

O RUST_LOG é lido do ambiente do processo: use --serve, não o daemon, para ver a saída no terminal.

shell 
$ RUST_LOG=opencode_claude_gateway=debug ocg --serve

Linhas que importam:

  • upstream ok — id que o cliente pediu e id do upstream.
  • upstream cache usage — opencode_ref resolvido e os acertos de cache de prefixo. É a única linha que mostra o destino real.
  • upstream rejected request — status, corpo e user_agent/session para atribuir a chamada.
