Pareamento e credenciais

O gateway não pede credenciais: pareia com o servidor OpenCode v2 e usa as integrações que já existem na máquina.

Fluxo padrão

POST /api/pair pelo CLI já autenticado, seguido de GET /auth/connect/:code com Accept: application/json. O session token resultante autentica as leituras com HTTP Basic opencode:<token>, fica cacheado em ocg.pair (0600) e é renovado automaticamente em 401.

config.toml 
# default: pareia com o serviço v2 selecionado
opencode_pair = true
# vazio = descobre pelo serviço selecionado
opencode_url = ""

Modo offline

Com opencode_pair = false — ou se o servidor estiver indisponível — o catálogo vem de opencode api get /api/model e as credenciais da tabela credential do SQLite, somente leitura. Nunca usa auth.json como fonte de verdade nem parseia opencode.jsonc. O caminho do banco vem de opencode debug paths db.

Como a credencial é escolhida

  1. settings.apiKey do catálogo, quando existir;
  2. provider → integrationID (/api/provider) → credencial ativa (/api/credential), preferindo a linha ativa da integração;
  3. fallback no SQLite;
  4. providers locais sem integração (Ollama) não recebem header de auth.

Credenciais ficam em cache por ~30s; a rotação no OpenCode não exige reiniciar o gateway.

Headers de sessão

Todo forward para o Go envia x-opencode-session: do x-claude-code-session-id do cliente, senão do x-opencode-session, senão de um fallback persistido em ocg.session.

Para um servidor v2 diferente do serviço selecionado (ex.: opencode serve --standalone), exporte OPENCODE_PASSWORD no ambiente do gateway antes de subir.
