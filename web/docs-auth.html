Autenticação

Por padrão o gateway aceita qualquer credencial em loopback. Um auth_token não-vazio muda isso: todo endpoint menos /health passa a exigi-lo.

Regras

  • O token é aceito via x-api-key: <token> ou Authorization: Bearer <token>.
  • Token errado ou ausente → 401 {"error":{"type":"authentication_error", …}}.
  • GET /health continua aberto (liveness).
  • Trocar o token exige reiniciar (--stop + --start); só editar o arquivo não afeta o daemon já rodando.
  • OCG_AUTH_TOKEN não-vazio sobrescreve o arquivo e é herdado pelo daemon filho — útil para teste sem editar nada.

O token do gateway não é uma chave da Anthropic. Ele só protege o seu gateway local; a credencial do provedor vem do OpenCode.

Configurar

config.toml 
auth_token = "troque-por-um-segredo"

No cliente, o valor vai em ANTHROPIC_AUTH_TOKEN (ver CLI) ou em inferenceGatewayApiKey (ver Desktop).

Verificar

shell 
# aberto
$ curl -s http://127.0.0.1:3737/health
# com o token
$ curl -s -H 'x-api-key: SEU_TOKEN' http://127.0.0.1:3737/v1/models \
    | jq -r '.data[].id'
# sem token deve dar 401
$ curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3737/v1/models
